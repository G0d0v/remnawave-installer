# Архитектура

G0d0v — установщик и менеджер окружения Remnawave для администратора Linux. Bash загружает проверенный релиз, а Python 3.10+ выполняет мастер, работу с API и обслуживание. Runtime использует стандартную библиотеку Python.

## Компоненты

| Модуль | Ответственность |
|---|---|
| `install.sh` | Проверка ОС/root, загрузка конкретного релиза, SHA-256, безопасная распаковка и launcher |
| `godov/config.py` | Проверка доменов, адресов, версий, портов, секретов и запись состояния |
| `godov/render.py` | Compose, Caddy, профиль Xray и сайт маскировки |
| `godov/api.py` | HTTPS API, создание токенов и возобновляемая регистрация объектов |
| `godov/system.py` | Проверка Linux, Docker APT, запуск сервисов и ограничение API ноды |
| `godov/backup.py` | pg_dump/pg_restore, TLS-хранилище, manifest и проверка архивов |
| `godov/bot.py` | Транзакционная привязка ShopBot и согласованный SQLite backup |
| `godov/operations.py` | Обновление с откатом, домены, диагностика, расписание и удаление |
| `godov/cli.py`, `godov/ui.py` | CLI и меню |

## Совместная установка

Схема трафика:

```text
Клиент VPN ─── TCP 443 ── Xray / Reality ─────── DIRECT → Интернет
                               │
Обычный HTTPS ─ TCP 443 ────────┴── target + PROXY v1
                                         │
                                  127.0.0.1:8443
                                         │
                                       Caddy
                                         ├─ panel.domain → 127.0.0.1:3000
                                         ├─ sub.domain/api/sub/* → панель
                                         └─ node.domain → статический сайт

HTTP 80 ──────────────────────────────── Caddy / ACME HTTP-01

Remnawave Panel (Docker bridge)
       ├─ PostgreSQL (внутренняя Docker-сеть)
       ├─ Valkey (Unix socket volume)
       └─ host.docker.internal:2222 → Node API (host network)
```

Панель соединяется с локальной нодой через `host.docker.internal:host-gateway`. Использовать `127.0.0.1` как адрес ноды внутри bridge-контейнера панели нельзя: этот адрес относится к самому контейнеру.

## Возобновление

Каждая установка получает случайный `install_id`. В каталоге записывается маркер владения, а API-объекты получают имя `G0d0v-ID`. Секреты и ID созданных ресурсов сохраняются после каждого шага. При повторном запуске API-объекты ищутся по этому имени. Неопределённый результат POST не вызывает слепой повтор того же запроса.

Установщик не удаляет стандартный профиль и squad существующей панели. Изменение активного профиля выполняется только для объектов текущей установки.

## Границы доступа

- Панель и её метрики публикуются только на `127.0.0.1`; PostgreSQL и Valkey не публикуют host-порты.
- Домен подписок пропускает только `/api/sub/*`; остальные пути возвращают 404.
- Для API ноды создаётся отдельная цепочка `G0D0V_NODE` в IPv4/IPv6 INPUT. Разрешены loopback, IP удалённой панели или bridge-сети локальной панели. Прочие подключения к NODE_PORT отклоняются через DROP.
- Правила этой цепочки восстанавливает systemd unit до запуска Docker. Общая политика firewall не заменяется. Host-network ноды не требует правил DOCKER-USER для своего API.
- Для новой панели создаются отдельные токены менеджера и ShopBot. Scopes берутся из каталога API панели. Административный JWT используется только для выпуска этих токенов с заголовком клиента, требуемым Remnawave 3.4.
- API не следует HTTP redirects с bearer-токеном. Удалённый URL панели требует HTTPS; HTTP допустим только для локального bootstrap панели.
- Подпроцессы вызываются массивами аргументов. Ввод не передаётся в `eval`, `shell=True` или shell-шаблоны.
- Каталог состояния имеет права 700, файлы секретов — 600. Операции записи выполняются через временный файл и `os.replace`.
- Одна изменяющая операция выполняется под файловой блокировкой. Просмотр меню и логов не удерживает блокировку фоновых копий.

## Копии и откат

PostgreSQL сохраняется через согласованный `pg_dump`. Конфиги и TLS-хранилище добавляются в архив с manifest SHA-256. Восстановление проверяет все пути и заголовки до распаковки, запрещает symlink/hardlink, дубликаты и выход за каталог. До остановки сервисов проверяются контрольные суммы и ID установки.

Перед восстановлением создаётся текущая копия. При ошибке происходит одна попытка возврата из неё. Если возврат тоже не завершился, команда сохраняет путь к копии и сообщает об ошибке. Результат `doctor` и тестовая подписка остаются необходимой проверкой после восстановления.

## Проверки

Малые тесты проверяют ввод, изоляцию портов, секреты, firewall, архивы и SQLite. HTTP-тесты используют локальный сервер с API-ответами и проверяют заголовки и повторный запуск. Linux smoke test разворачивает настоящие Docker-образы в одноразовом runner и передаёт HTTP-трафик через клиент VLESS/Reality/Vision. Для TLS в smoke используется внутренняя CA Caddy; публичный ACME требует реального домена и сервера.
