# Эксплуатация G0d0v Remnawave

Инструкция для администратора уже установленного сервера. Для первого запуска см. [README](../README.md).

## Проверьте установку

1. На сервере откройте статус:

   ```bash
   godov-remna status
   ```

   Контейнеры должны находиться в состоянии `running`; у панели, PostgreSQL и Valkey — `healthy`.

2. Запустите диагностику:

   ```bash
   godov-remna doctor
   ```

   Проверьте TLS доменов и подтверждённый запуск Xray. Неуспешная проверка возвращает exit code 1.

3. Посмотрите доступы и войдите в панель:

   ```bash
   godov-remna credentials --show-secrets
   ```

4. В ShopBot создайте тестовый тариф для добавленного хоста, выдайте тестовый ключ и проверьте подключение в клиенте. Пробная выдача должна использовать внутренний squad, созданный установщиком.

## Подключите бота на другом сервере

Файл подключения содержит API-токен. Передавайте его по SSH и храните с правами 600.

1. На сервере панели экспортируйте параметры:

   ```bash
   godov-remna export-bot
   ```

   Результат: `/opt/godov-remnawave/shopbot-connection.json`.

2. Передайте файл на сервер бота:

   ```bash
   scp /opt/godov-remnawave/shopbot-connection.json \
     root@BOT_SERVER:/root/shopbot-connection.json
   ```

   Замените `BOT_SERVER` на IP или SSH-имя сервера бота.

3. На сервере бота установите CLI и выполните привязку:

   ```bash
   bash <(curl -fsSL https://raw.githubusercontent.com/G0d0v/remnawave-installer/v1.0.0/install.sh) \
     bind-bot --connection /root/shopbot-connection.json \
     --container remnawave-shopbot
   ```

   Команда устанавливает CLI, затем меняет только привязку ShopBot. Панель и ноду на сервере бота она не разворачивает. Если CLI уже установлен, используйте `godov-remna bind-bot --connection /root/shopbot-connection.json`.

4. Откройте управление хостами в ShopBot и проверьте строку `G0d0v-ID`. Тарифы создайте в боте вручную: их стоимость и длительность установщик не выбирает.

Для SQLite на хосте вместо Docker укажите файл базы:

```bash
godov-remna bind-bot --connection /root/shopbot-connection.json \
  --database /opt/remnawave-shopbot/users.db
```

Замените путь к SQLite на путь своей установки. Сначала выполняются проверка схемы и SQLite backup, затем одна транзакция добавления хоста. Токен передаётся контейнеру через stdin, а не через аргументы процесса или переменные окружения.

## Установите только ноду вручную

1. В существующей панели откройте создание ноды и скопируйте `SECRET_KEY` из предложенного compose.
2. На сервере ноды запустите установщик и выберите **Только нода · вручную**.
3. Укажите реальный исходящий IP сервера панели и тот же `NODE_PORT`, который выбран в панели. Вставьте `SECRET_KEY` в скрытый ввод.
4. Если используете selfsteal, укажите домен ноды, тему сайта и email для ACME.
5. После установки импортируйте `/opt/godov-remnawave/xray-profile.json` в **Config Profiles** панели.
6. Назначьте профиль и inbound `G0D0V_VLESS_REALITY` ноде.
7. В панели создайте host с публичным адресом ноды, портом 443 и SNI, указанным в профиле. Для VLESS используйте Vision.
8. Создайте внутренний squad с этим inbound. Проверьте статус ноды и тестовое подключение.

Ручной режим устанавливает агент и выдаёт профиль. Он не регистрирует host или squad через API.

## Добавьте ноду автоматически

1. В панели Remnawave 3.4.x создайте API-токен с правами на `config-profiles`, `nodes`, `hosts`, `internal-squads`, `keygen` и инструмент генерации X25519 в `system`.
2. На сервере ноды выберите **Нода в существующую панель · автоматически**.
3. Введите HTTPS URL панели, токен, публичный адрес ноды и исходящий IP панели. Для selfsteal подготовьте A/AAAA домена ноды.
4. Дождитесь сообщения об успешной связи с Xray. Установщик создаёт отдельные объекты с именем `G0d0v-ID`, не удаляя стандартные профили и squads.

API-токен существующей панели не перевыпускается автоматически. Если панель защищена внешней авторизацией reverse proxy, разрешите обращения с API-токеном к нужным `/api/*` маршрутам.

## Установка за NAT

Проверка DNS сравнивает адреса доменов с адресами интерфейсов сервера. Если публичный IP существует только на внешнем NAT, укажите:

```bash
godov-remna install --skip-dns-check
```

Для сохранённой незавершённой установки выполните:

```bash
godov-remna resume --skip-dns-check
```

Флаг пропускает проверку соответствия IP. Он не отменяет требования ACME: внешние 80/tcp и 443/tcp должны попадать на сервер. Базовая установка не открывает порты у провайдера и не меняет общую политику UFW/firewalld.

## Измените домены и маскировку

1. Создайте DNS-записи новых доменов и дождитесь их разрешения.
2. На сервере выполните нужную команду:

   ```bash
   godov-remna domains
   ```

   Для изменения сайта и домена selfsteal выполните:

   ```bash
   godov-remna selfsteal
   ```

3. Проверьте параметры и подтвердите применение. Перед изменением создаётся архив; при ошибке запуска выполняется откат. В режиме удалённой панели также возвращается прежний Reality-профиль.
4. Запустите `godov-remna doctor`. Если изменился URL панели или домен подписок, заново экспортируйте подключение и выполните `bind-bot`.

На время перезапуска Xray и Caddy соединения могут прерываться. Переключение уже установленной ноды между внешним target и selfsteal, а также смена режима сервера не поддерживаются: для такой миграции создайте новую ноду.

Для своего HTML измените `/opt/godov-remnawave/site/index.html`. Каталог доступен Caddy только для чтения. Сохраните собственный сайт отдельно: изменение темы через меню заменяет `index.html`.

## Сохраняйте резервные копии

Создайте согласованную копию PostgreSQL, файлов конфигурации, сайта и хранилища Caddy:

```bash
godov-remna backup
```

Команда печатает путь к `godov-TIMESTAMP.tar.gz`. Для проверки целостности архив содержит SHA-256 каждого файла. PostgreSQL сохраняется через `pg_dump --format=custom`; копирование активного Docker volume базы не используется.

Чтобы включить ежедневные копии с хранением последних семи архивов, выполните:

```bash
godov-remna backup-schedule
```

Проверьте таймер:

```bash
systemctl status godov-remna-backup.timer
systemctl list-timers godov-remna-backup.timer
```

Для отключения расписания выполните:

```bash
systemctl disable --now godov-remna-backup.timer
```

Копии находятся на том же сервере. Для защиты от потери диска регулярно переносите их во внешнее защищённое хранилище. SQLite бота сохраняется отдельно при привязке и не включается в архив Remnawave.

## Восстановите установку

Восстановление заменяет базу и конфигурацию. Оно рассчитано на архив **этой же установки** с тем же ID и режимом.

1. Запишите путь к архиву.
2. На сервере выполните:

   ```bash
   godov-remna restore BACKUP_PATH
   ```

   Замените `BACKUP_PATH` на полный путь к архиву. Сначала проверяются структура и контрольные суммы; сервисы останавливаются после проверки и сохранения текущей копии.

3. Подтвердите замену состояния. При ошибке восстановления установщик пытается вернуть копию, созданную перед операцией.
4. Запустите `godov-remna doctor` и проверьте тестовую подписку.

Автоматический перенос архива на чистый сервер другой установки не поддерживается. Для аварийной миграции сохраните код релиза, root-каталог состояния, архив и внешний backup бота; восстановление на новом сервере требует отдельной процедуры с проверкой ID, DNS и IP панели.

## Обновите версии

Установщик не переключает контейнеры на `latest`. Чтобы применить выбранные версии, выполните:

```bash
godov-remna update --panel-version 3.4.11 --node-version 3.4.6
```

Для изменения версии Caddy укажите её отдельно:

```bash
godov-remna update --caddy-version 2.11.9
```

Перед обновлением создаётся backup. При ошибке pull, запуска или связи с нодой возвращаются конфигурация и PostgreSQL из копии. Бинарные volumes PostgreSQL не переводятся между major-версиями этой командой. Перед выбором другого major Remnawave изучите его миграционные требования: установщик проверялся с 3.4.x.

Команда `update` обновляет контейнеры. Для обновления самого CLI запустите bootstrap нужного опубликованного релиза.

## Перевыпустите API-токены

Токены, выданные новой панелью, действуют 365 дней. До истечения срока откройте **Доступы к панели и API → Перевыпустить токены** или выполните:

```bash
godov-remna tokens
```

Введите пароль администратора. Если он не менялся, нажмите Enter для использования сохранённого пароля. Команда выдаёт два токена с отдельными scopes и обновляет файл доступов. Старые токены не отзываются автоматически: сначала переподключите все экземпляры бота.

После перевыпуска выполните `bind-bot` на этом сервере или заново `export-bot` и импорт на сервере бота. Затем отзовите ненужные старые токены в панели. Для внешней панели используйте её интерфейс выпуска токенов.

## Найдите причину ошибки

Начните с диагностики и логов нужного сервиса:

```bash
godov-remna doctor
godov-remna logs panel --follow
godov-remna logs node --follow
godov-remna logs caddy --follow
```

Типовые причины:

| Симптом | Что проверить |
|---|---|
| Порт занят | Другой nginx/Caddy/VPN; установщик не останавливает их автоматически |
| TLS не выпускается | DNS A/AAAA, CDN proxy, входящий 80/tcp, исходящий HTTPS, лимиты ACME |
| Нода не подключается | Исходящий IP панели, `NODE_PORT`, firewall провайдера и `SECRET_KEY` |
| Панель работает, VPN нет | Запуск Xray, назначение профиля и squad, SNI и публичный 443/tcp |
| `HTTP 401/403` | Срок API-токена и права scopes; внешняя защита API в reverse proxy |
| Ошибка установки Docker | Доступность Docker APT, конфликтующие пакеты, `/var/log/apt/term.log` |
| Бот не видит хост | Правильный контейнер/users.db; тариф привязан к созданному хосту |

После устранения причины продолжите сохранённую установку:

```bash
godov-remna resume
```

Секреты не передаются через аргументы CLI. Сообщения API-ошибок не копируют тело ответа панели, которое может содержать токен. Не публикуйте `state.json`, `.env`, файлы доступов или архивы в issues.

## Удалите контейнеры

Чтобы сохранить backup, удалить контейнеры и оставить Docker volumes, выполните:

```bash
godov-remna uninstall
```

Если требуется удалить также данные volumes, используйте:

```bash
godov-remna uninstall --purge
```

Обе команды требуют подтверждения и сначала создают backup. Сохраняются архивы и код CLI; посторонние Docker-проекты, общая конфигурация Docker, nginx и правила firewall не удаляются. Ограничение API ноды и таймер копий этой установки отключаются. Объекты, созданные в удалённой панели, остаются для ручной проверки и удаления.
